# 场景 spec 模板（每个场景一份）

一个场景一份 spec，写清楚到"agent 不用问就能动手，人不用跑就能验收"。
下面是模板 + 填写说明；跑过的真实例子见 [`03-examples.md`](03-examples.md)。

---

```markdown
## sNN <name>（t0–t1，bar a–b）

**歌词**：<EN 行> / <ZH 行>            # 从 engine/timeline.py 抄，spec 里不改歌词
**一句话**：这台机器在这一段"在做什么"（不是"给人什么感觉"）

**分层**（必须能一句话说清哪层画在哪）
- 背景：<网格 / 星尘 / 扫描线底色 / 渐变色块 …>
- 主体：<本段的视觉中心，占多少格>
- 读数：<HUD 面板、角落小字、进度条，位置要写行列>

**运动**（按时间切片，每片 ≤ 2 s）
- 0.0–0.6 s：<进入方式：淡入 / 打散重组 / 从边推进 / 直接出现>
- 0.6–2.0 s：<稳态在做什么：呼吸、环流、抖动、字符闪烁>
- … 
- t1-0.4–t1：<退出方式，必须能接下一段（不要用硬切闪白）>

**颜色**
- 主色：<palette 里的键名，例如 P.primary / P.gold>
- 辅色：<…>
- 告警/强调：<…>（出现条件写清楚）

**固定文案**（要逐字给出，别让 agent 编）
- 左上：<面板标题> / <行 1> / <行 2> …
- 右上：<…>

**约束**
- 不许画到舞台外；不许改页眉/字幕条
- <本段特有的禁忌：尺寸不变、不要全屏闪、不要删除已有 UI …>

**验收静帧**：t = <t0+0.4> / <中点> / <t1-0.3>        # 三张，1080p
**通过标准**：<列 2-3 条可判定的，例如"∞ 在两帧里行数相同"、"面板文案与 spec 一致">
```

---

## 填写时的三条经验

1. **"一句话"写机器在干什么，不写情绪。**
   ✗ "这一段要让人心碎"
   ✓ "机器在擦除记忆：每 4 拍删掉一行，行数减到 0 后开始逐格重建心形"

2. **运动切片的时间要给数字。** 人看视频能感觉到"太急"，agent 不能；
   给它"0.0–0.6 s 淡入、0.6 s 后开始环流"这种刻度，它才能写对缓动。

3. **固定文案必须逐字。** 让 agent 自己编 HUD 文案，它会写出风格不一致的中英混排；
   spec 里给死，它只负责排版。

## 关于时长

- 一个场景 3–15 s 最合适；超过 15 s 的（比如 88.8–103.6 s 的 transform 段）
  拆成"循环单元 + 参数随小节变化"，别写成一条 900 行的直线代码。
- 场景切换点对齐小节（`bar`），不要对齐到小数点后三位——除非那句话真的在拍点中间进。
