# 给 agent 的现场守则

贴在 brief 后面（或作为它的系统提示的一部分）。这些是"多进程按帧并行渲染"带来的坑，
不是风格偏好——违反了会直接产出不一致的帧。

---

```
现场守则（必须遵守，违反会导致渲染结果不一致）：

1. 帧是并行的。render.py 用多进程按帧号分派，同一时刻有 8-16 个 worker 在不同帧上。
   - 场景里不许有模块级可变状态（不要用 global 缓存"上一帧的样子"）。
   - 需要跨帧的效果（拖尾、余像）用确定性的方式算：ctx.fi 或 ctx.since(t_event)，
     而不是"记住上一帧"。

2. 随机数只有一个来源：ctx.rng(seed)。
   - 它按帧号播种，所以同一帧永远得到同一串随机数。
   - 不要用 random / np.random 全局状态，也不要用 time 播种。

3. 时间只有一个来源：ctx。
   - ctx.t 全片秒；ctx.local 场景内秒；ctx.beat_p 拍内相位（0..1）；
     ctx.bar_p 小节内相位；ctx.pulse 每拍衰减脉冲；ctx.bands 频谱；
     ctx.line 当前歌词。
   - 不要 time.time()、不要读系统时钟。

4. 文字光栅化很贵。
   - F.text_mask(text, px_h) 有缓存，但文本或字号变了就会重算。
   - 每帧要画大段文字时，先在场景第一次调用时算好掩码并缓存到局部变量（不是模块级），
     或者用固定字号让缓存命中。

5. 不要越界。
   - 舞台是 Frame(45, 192)。越界写入会被静默丢弃（看起来像"画丢了"）。
   - 想要页眉/页脚/字幕，改 chrome.py，不要在场景里画。

6. 后处理会吃细节。
   - post.py 会加扫描线、色散、噪点。1 格宽（18 px 高）的细笔画在 1080p 下会被吃掉，
     重要笔画至少 2 格宽，或用 palette 的亮色阶。

7. 交付前自检（把结论贴给我，不要贴日志）：
   - python tools/still.py --t <三个验收时刻> --out qa/sNN_<t>.png
   - python tools/check_timeline.py --start <t0> --end <t1> --stride 47
   - 报告：改了哪个文件、新增/删除多少行、三张静帧的路径、check 的结论

8. 一次只改一处。
   - 收到多条反馈时，先改第一条并交付静帧，等我确认再改第二条。
   - 不许顺手重构其它场景、不许改 palette 的既有颜色、不许改 timeline 的歌词。
```

---

## 为什么第 1 条最重要

渲染 4K 整片要 90 分钟，所以一定是并行的。并行的前提下，
"模块级缓存上一帧"这种写法在单测里看着没问题，出片时会变成随机抖动/闪烁，
而且**无法复现**（换个 worker 数就换一种坏法）。所以宁可让 agent 多算一点，
也不要让它记住任何跨帧状态。

## 为什么第 8 条能省你一整天

agent 的默认行为是"把你说的都做了，顺便把看到的都改了"。一次改五处之后，
如果画面变差，你无法归因；而它自己是看不出"变差"的（看不见视频）。
一次一处 = 每次都能确定是不是这一处的问题。
