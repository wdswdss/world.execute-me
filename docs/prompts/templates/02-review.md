# 打回（review）模板

改片的时间 90% 花在这里。打回的关键是：**一句话说清"哪一帧、哪里不对、要变成什么"**。
下面四种是真正用过的形态，按使用频率排。

---

## A. 症状 → 期望 → 约束（最常用）

```
<时间点/帧号> 的<画面区域> <症状>。
我要的是<期望>。
<约束：别顺手改别的>。
```

真实例子：

> 22 秒满屏的代码特效把原来的 UI 都盖住了。绘制标题的时候，原来的 UI 不需要删掉，
> 你只要把代码特效画在 UI 上面就行。不要再重新生成标题。
> 这样你后面也不需要再生成那一端。

> 41 秒开始的无限符号不应该由远及近地放大，应该做成固定大小的无限符号动画来跑。

---

## B. 数值化（需要精确到格/帧的时候）

```
<对象> 在 t=<a> 是 <数值>，在 t=<b> 是 <数值>。
我要 <目标数值>，且 <是否允许变化>。
```

真实例子：

> ∞ 在 41.8 s 约 24 行高、97 列宽，到 44.0 s 涨到 44 行高、180 列宽，把舞台吞了。
> 我要整段固定 24 行左右，大小完全不变，只让亮度沿曲线流动。

> 标题在 144 列画布里占 135 列，左右只剩 50/41 px；改成 8 格高（135 列）再试，
> 7 格时笔画被阈值吃掉、字形糊了。

---

## C. 全片级（收尾/回归检查）

```
全片检查 <N> 帧：
- 0 异常 / 0 NaN
- EN 行里没有 CJK
- 所有字形都有掩码（没有方块/空格）
- 场景总分贝 <目标>，没有 > <阈值> 的尖峰
报告放在 <路径>，只把结论贴给我。
```

真实例子：

> 抽 4349 帧跑一遍：0 异常、0 写中文进英文行、0 未知字形、0 NaN。
> 唯一 FAIL 是 schedule 结束 211.905 s 但 DURATION 215.905 s（差 4 s 是尾留白，预期）。

---

## D. 只改一句（字幕/文案类，最容易过度施工）

```
把 <位置> 的 <旧内容> 改成 <新内容>，<出处/依据>。
只重渲 <区间>，不要动其它帧。
```

真实例子：

> 2 分 39 秒到 41 秒的英文歌词改一下，改成原版的多语言（官方歌词里是
> ein, dos, trois, 넷, fem, 六, execution）。
> 只重渲这一句覆盖的 220 帧，其它不要动。

---

## 反模式（这样写一定返工）

| 写法 | 为什么不行 | 改成 |
|---|---|---|
| "再好看一点" | 没有可判定的目标 | "主体占屏从 1/3 变成 1/2，字符密度提一档" |
| "你自己判断" | agent 会顺手改 5 个场景 | "只改 s03，其它文件不许 diff" |
| "整体重做" | 前面已经验收的部分全白费 | "只改 21–25 s；14–21 s 保持 v33 的样子" |
| 一次列 6 条反馈 | 后 4 条会被上下文挤掉 | 一次 1–2 条，改完再给下一批 |
| 贴整段代码让 agent 改 | 烧上下文、且它看不出位置 | 贴函数签名 + 行号 + 一句话 |

## 打回之后

让它**先复述**再动手，并且要求它在报告里写"哪一帧我验过、差多少"。
如果它连续两次验证不出问题，通常不是它笨，是**验收条件本身没写清**——
回去改 spec，比再打回一次快。
