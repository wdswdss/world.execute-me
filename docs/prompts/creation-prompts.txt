合并使用版

下面是把上述需求合并后的创作提示词，适合从头描述同一作品；它是整理后的重写版本。

请根据 Mili《world.execute(me);》的歌词和表达，制作一支 ASCII 字符动画 MV，并把它做成可以发布的 4K60 视频：画面由代码逐帧画在一块 192×60 的字符网格上（每格 10×18 px，整体放大 2 倍输出 3840×2160@60fps），不拼接素材、不用扩散模型。

整片保持程序界面风格：顶部页眉、玻璃面板、模块化读数、CRT 扫描线与色散；字幕独立占底部两条固定区域，中文用雅黑、英文用等宽字体，与歌词时间轴同步；音频为原曲加一层音效，字幕层要能单独重渲替换。

歌词段落各自要有明确的语义动作，共 21 个场景：

- 开场：数据逐步填满屏幕，初始化逐项检测、逐项完成。
- 歌名段（00:15.8–00:29.7）：间奏里把界面字符全部打乱铺满全屏，再重组成 WORLD.EXECUTE(ME);。
- 无限段（00:40.7–00:44.5）：∞ 保持固定大小，不做由远及近的放大；用一条沿曲线环流的光带让它在原地“运行”。
- 后半段：刺激、满足、快乐与执行、被困、心跳心电图、蔬果与猫、身份改写与昼夜、故障累积、内存清空、多语言报数、唯一执行、学习系统崩坏、心形、卡在 99% 的结尾——沿用姊妹仓库里已经确认的画面语言。
- 多语言报数（02:38.9–02:41.6）：主画面按语言轮转，字幕恢复原版写法 Ein, dos, trois, 넷, fem, 六, execution，不要罗马化。
- 结尾：进度条卡在 99%，最后一句 EXECUTION 响起变成同风格红色大字，结束语只留英文 PROCESS ENDED. THE LOOP REMAINS.。

两处必须遵守的衔接约定：

- 标题成形的段落里，原来的 UI 不要被删掉：代码风暴和标题只往上面叠加，不要出现“只剩标题”的空窗，也不要在后面再把消失的 UI 重新生成一遍。
- 22–25 秒的过渡不要用整屏闪烁，改成一个连续动作：由代码重新汇聚出显示端和歌词。

改任何单一场景时只重渲那一段再拼回去，用像素差核对拼接点，避免整片重渲。

修改后保留前面已经确认的设计。最后导出 4K60 母版，并做一张同视觉语言的封面（∞ + 心 + 标题，无附加文字），同时出 16:9 与 4:3 两个原生版面。
