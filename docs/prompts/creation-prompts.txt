world.execute(me); — ASCII 终端 MV｜创作提示词整理


以下按实际提出需求的顺序整理，共 37 轮。第 01–25 轮是把这支 MV 做成终端播放器的那一段：21 个场景的语义动作、心跳心电图、报数接管、心形空洞，都是在这几轮里逐段定下来的；第 26 轮起转到视频管线，把它做成能发布的 4K60 母版，并补上封面与文档。

开场需求已整理为可独立阅读的版本；后续保留原有指令的语气，并为“这里”“这两句”等表达补充场景位置。场景位置属于整理注释，不是当时提示词的原文。已纠正少量英文拼写与标点。

## 合并使用版

下面是把上述需求合并后的创作提示词，适合从头描述同一作品；它是整理后的重写版本。

请根据 Mili《world.execute(me);》的歌词和表达，制作一支可以在终端运行的 ASCII 字符动画 MV，并把它做成可以发布的 4K60 视频：画面由代码逐帧画在一块 192×60 的字符网格上（每格 10×18 px，整体放大 2 倍输出 3840×2160@60fps），不拼接素材、不用扩散模型。使用提供的音乐与歌词时间轴，配上同步的中英双语字幕。

整体保持程序界面风格。动画要复杂、密集，有全屏大范围运动；利用 CRT 视觉语言表现扫描、残影和故障。底部频谱只占一条细带，右上角不要中文，双语字幕保留独立且稳定的阅读区域。字幕层要能单独重渲替换：母版不带字幕，字幕作为 PNG 序列叠上去。

开场表现数据填充和逐项初始化。进入歌名前的间奏，把界面里的字符全部打乱，让它们铺满屏幕，再重组成 WORLD.EXECUTE(ME);。

每个歌词段落都要有明确的语义动作：

- 无限段（00:40.7–00:44.5）：∞ 保持固定大小，不做由远及近的放大；用一条沿曲线环流的光带让它在原地“运行”。
- STIMULATION：做出贴合“刺激”主题的动画；紧接着的 SATISFACTION 使用进度条风格。
- 快乐与执行段：根据歌词重新设计全屏动画，加入 EXECUTION 元素和两侧的数据滚动。
- 被困与模拟世界段：增强画面规模和运动，让“被困”成为看得见的状态。
- eggplant、tomato、tabby cat：保留具象角色动画；在已有工程中恢复此前确认的版本。
- F→M 与 AM→PM：分别重构身份切换和昼夜变化的动画。
- 感受心跳段：使用心电图效果。
- 离开段：节点逐步断开，过程更丰富、持续更长；“You have left” 之后 glitch 越来越多。
- 内存清空与心灰意冷段：强化重建心形与失败的视觉表达。
- 多语言报数段（02:38.9–02:41.6）：让报数成为主画面，按唱词依次显示 EIN / DOS / TROIS / 넷 / FEM / 六，字幕按原版写法，不要罗马化。
- THE ONLY EXECUTION 段：突出病娇、占有欲和唯一执行的意味。
- 学习段：使用机器学习／LLM 工作原理的崩坏演示。
- 心形修正：填补不应存在的空洞和三个局部凹陷，同时检查后段心形中的同类问题。
- 结尾：进度条卡在 99%；最后一句 EXECUTION 响起时，变成同风格的红色 EXECUTION 大字。结束语仅保留英文 PROCESS ENDED. THE LOOP REMAINS.。

另有两处必须遵守的衔接约定：

- 标题成形的段落里，原来的 UI 不要被删掉：代码风暴和标题只往上面叠加，不要出现“只剩标题”的空窗，也不要在后面再把消失的 UI 重新生成一遍。
- 22–25 秒的过渡不要用整屏闪烁，改成一个连续动作：由代码重新汇聚出显示端和歌词。

改任何单一场景时只重渲那一段再拼回去，用字幕帧号对齐切口，并用像素差核对拼接点，避免整片重渲。

修改后保留前面已经确认的设计。最后导出 4K60 母版，并做一张同视觉语言的封面（∞ + 心 + 标题，无附加文字），同时出 16:9 与 4:3 两个原生版面。
