# 提示词：怎么让一个 agent 写出这支 MV

这支 MV 是"人给意图 + agent 写场景 + 静帧验收"循环出来的产物。
这一页是那套循环的可复用版本——**为什么这么写、每层提示词长什么样、什么时候该打回**。
可直接复制的模板在 [`prompts/`](../prompts/)。

## 0. 前提：agent 看不见画面

这是所有提示词设计的起点。写代码的 agent 能读源码、能跑脚本、能看**静帧**，
但它没有"播放视频"的感知。所以：

- **验收必须落到静帧和数字上**：不要写"这段要燃一点"，要写"t=41.8 s 的 ∞ 是 24 行高"。
- **一次只做一件事**：一个场景、一处改动、一句字幕。让它同时改 5 个场景，
  它会在上下文里丢失第一个场景的约束。
- **让产物落盘、别让它进对话**：静帧写 `qa/`，日志写文件，只在对话里回报
  "哪一帧、差多少、结论"。这支 MV 的旧会话就是死在 1.5M tokens 的一次性长上下文上。

## 1. 三层提示词

### 第一层：项目 brief（只写一次）

给 agent 定死不可协商的东西：网格尺寸、图层边界、技术栈、禁止项、验收命令。
模板：[`prompts/00-project-brief.md`](../prompts/00-project-brief.md)。

关键是**把"不许做什么"写清楚**，因为它们比"要做什么"更容易被违反：

> 场景只能画 45×192 的舞台；页眉/走带条/字幕条/页脚由 chrome 负责，场景不许碰。
> 只用 numpy + Pillow；不许调用外部素材、不许联网、不许生成图片再贴上去。

### 第二层：场景 spec（每个场景一份）

一个场景 = 一份 spec。写成**可验收的参数表**而不是文学描述：

```markdown
## s03 infinity（29.730–44.500，bar 65–96）
歌词：If I approach infinity, then you can be my limitations
主体：屏幕中央一个 90×22 格的 ∞，笔画用 ░▒▓█ 填充
运动：0-3.7s 点阵 → 圆；3.7-7.4s 正弦；7.4-11.1s 极限曲线；11.1s 起 ∞ 常亮
约束：∞ 的尺寸在整个第四阶段**不变**；亮度沿曲线环流（一条亮带绕行）
读数：左上 APPROACH INFINITY 面板、右上 MY LIMITATIONS 面板（固定文案）
验收静帧：t = 30.1 / 41.8 / 44.4
```

模板：[`prompts/01-scene-spec.md`](../prompts/01-scene-spec.md)。
三个真实例子：[`prompts/03-examples.md`](../prompts/03-examples.md)。

### 第三层：打回（review）

改片 90% 的时间花在这里。有效的打回有三种形态：

1. **症状 → 期望 → 约束**（最常用）
   > 22 秒满屏的代码把 UI 全盖住了。绘制标题的时候原来的 UI 不要删掉，
   > 把代码特效画在 UI **上面**就行，不要再重新生成标题。

2. **数值化**
   > ∞ 在 41.8 s 是 24 行高，44.0 s 涨到 44 行，把舞台吞了。
   > 我要整段固定 24 行、大小不动。

3. **全片级**
   > 抽 4000 帧检查：无异常、无 NaN、EN 行没有混进中文、所有字形都有掩码。

模板：[`prompts/02-review.md`](../prompts/02-review.md)。

## 2. 循环节奏

```
spec ──► agent 写代码 ──► tools/still.py 出静帧 ──► 人看 ──┬─► 过：进渲染队列
                                                          └─► 打回：写上面那种反馈
```

- **一个场景一个会话**（或至少一个场景一次提交），做完就让它总结"改了什么、验收帧在哪"。
- **静帧先看 320 px 缩略图**确认构图，再开 1:1 看字形；否则每张图都在烧上下文。
- **让 agent 自己先做一次像素/数值自检**（`check_timeline.py`），人只看结论。

## 3. 真实踩过的坑（写进 prompt 能省下整轮返工）

| 坑 | 现象 | 写进提示词的说法 |
|---|---|---|
| 歌词里混 CJK | 英文行里塞了「六」「넷」，播放器上像乱码 | EN 行只放拉丁字符；中文进 ZH 行 |
| 每帧重新光栅化 | 4K 渲染慢到 3 fps | 文字掩码要缓存；h_cells 变了才重算 |
| 用 `time.time()` | 多进程渲染同一帧结果不同，拼接处抖动 | 时间只能从 `ctx` 拿；随机数用 `ctx.rng(seed)` |
| 场景画到页眉 | 和 chrome 打架、拼出双字 | 场景只画舞台 45×192 |
| 全屏闪白 | 观众说"太突兀，像换了个视频" | 闪白 ≤ 0.08 强度、≤2 帧，或用亮度渐变代替 |
| 一次性长上下文 | 1.5M tokens 后会话直接死掉 | 一个场景一个会话；中间产物落盘不进对话 |

## 4. 起始 prompt（整段可复制）

```
我要给 Mili《world.execute(me);》做一支非官方同人 MV，纯代码绘制，不用任何素材/生成图。

约束（不可协商）：
- 画面是一块 192×60 的字符网格，舞台 45×192，格子 10×18 px，60 fps
- 每帧 = 每格一个字符 + 前景色 + 背景色，最后统一过一遍 CRT 后处理（扫描线/色散/噪点）
- 场景代码只画舞台，页眉/走带条/字幕条/页脚由 chrome 统一画
- 只用 numpy + Pillow；不联网、不读外部图片、不用音视频素材
- 时间只能从 ctx 拿（t / beat / bar / 音频特征），不许 time.time()
- 随机数只用 ctx.rng(seed)，保证任意一帧能单独重渲且结果一致

先做 s01「开机」：0-14.96 s，屏幕像一台老机器通电自检，逐行打印、进度条爬升、
最后稳定成一块终端界面。给我：
1. 代码（engine/scenes/s01_boot.py，实现 draw(ctx) -> Frame）
2. t = 2.0 / 8.0 / 14.0 三张 1080p 静帧
3. 一句话说明你用了哪几层（背景/主体/读数）
```

然后按 §1 第三层的方式打回，一次改一处。

## 5. 想做"你自己的那支"？

把 brief 里的歌名、时长、BPM、场景数换掉，其余不用改——这套提示词描述的是
"用字符网格画一支 MV"的工程约束，跟具体哪首歌无关。
`engine/timeline.py` 是唯一的时间真相，先填歌词再让 agent 一个场景一个场景写。
